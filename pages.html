§9.8 Prompt 抽象

三层结构与回写闭环

层放什么稳定性本章位置
项目层品牌、产品原则、布局断点、token、格式、硬规则 UR1–UR9、无障碍极少变；改动须回溯第 6 / 8 章§9.2
数据层类型、状态文案、mock 规则（价格自洽、统一时钟、共享种子）随对象模型变§9.3
页面层单页任务、区块、交互与状态、本页规则投影、跨页一致、演示状态每页一份，按模板写§9.4–§9.6
校验层生成后逐条核对；不通过改结果、不改规则随缺陷回写增长§9.7

回写闭环：生成 → §9.7 核对 → 缺陷分类（§9.8.3）→ 若是 prompt 漏写，补进该页 prompt；若多页共性，上提到 §9.2 / §9.3；若暴露了未决产品问题，进 PD（附录 A.2）先决策再生成。

页面 prompt 模板

Build <page name> at "<route>" (<audience: user | merchant | ops>; <device: mobile-first | desktop 1280 | tablet 1024×768>).

## Job
<One sentence: what the person must understand or decide on this page.>

## Data
- Types: <types from §9.3>. Lotteries: <ids and statuses used>.
- Time: compute everything against PROTO_NOW (2026-09-26 18:00 JST).
- Shared facts: <numbers that must match other pages, e.g. k = 3.4, monthly usage ¥12,000, my slot #02>.
- Generated data: <seeded generator if cards are listed — never hand-write card lists>.

## Layout (top to bottom; mobile → ≥768 → ≥1024)
1. <section>: <content, Japanese copy in 「」>
2. ...

## Interactions & states
- <interaction> → <result>. Deep links: <#hash forms>.
- States: normal / loading / empty / error / <page-specific>.

## Rules on this page
- <UR / I / PD that apply here, restated concretely>.
- Do NOT <the specific failure this page tends to produce>.

## Demo states (prototype only)
- <states the reviewer must be able to switch to: failing validation, interruption, tamper, etc.>

## Delivery
Single static HTML file, inline CSS/JS, Google Fonts only, noindex, prototype control strip
showing 「原型时钟 2026-09-26 18:00 JST」. Link to other prototype pages by relative file name.

写 Do NOT 的标准：只写本页最容易生成错的那一条（例如随机模式满员前显示逐位售出、工位端出现「再開」），不重复 §9.2 已有的全局禁令。

缺陷分类

类现象根因对策（已写入模板）
D1 数据不自洽示例价格隐含溢价 >400%；9/28 写成周日；k 在两页不同示例数字手写数据由规则 / 种子生成；跨页事实写进 Shared facts
D2 规则投影缺失随机模式显示逐位售出；归属可自批；"原始画面"含系统信息规则只写了原则，没写在本页的具体形态Rules on this page 具体化 + 一条 Do NOT
D3 决策未定支付方式（便利店、3DS）、深夜阈值口径生成页面时才遇到产品问题停下来进 PD 决策（PD9 / PD10），再生成
D4 交付约束冲突prompt 要 recharts，仓库不允许构建；CSS 类名冲突技术栈假设与仓库规则不一致Delivery 段固定写单文件规则
D5 演示性不足向导初始全通过，看不出实时校验；断线、篡改无法演示prompt 只描述正常态Demo states 段列出必须可切换的状态

结论

结论：17 条记录里 D2（规则投影缺失）最多 —— 第 6 / 8 章的原则对生成工具不够具体，必须在页面 prompt 里写成该页的具体形态。D3 只出现一次但代价最大：它说明生成原型本身是一个决策检查点，P1 页面（直播间、DRAFT）生成前应先过一遍 PD 清单。

全局层面：各页"现在"不同；artifact 与仓库两处原件 → 统一原型时钟；仓库为唯一原件，UI-08 起只发预览站（回写 §9.3、§9.1、CLAUDE.md）。

页面 prompt（§9.4–§9.6 原文）
Build "/verify/[lotteryId]" (works without login; also used as a public share page).

Sections:
1. Explanation in plain Japanese (3 steps with icons):
   ① 販売開始前にシードのハッシュを公開 ② 満員後に参加者と外部ビーコンを合成
   ③ 公開アルゴリズムで割り当てを計算 → 誰でも再計算できます
2. Inputs table (monospace, copy buttons): seedCommitHash, commit time, serverSeed (revealed),
   participantsHash, beacon source/round/value/fetchedAt, algorithmVersion.
3. 「ブラウザで再計算する」 button: runs a deterministic mock computation client-side
   (SHA-256 of serverSeed must equal seedCommitHash; then a seeded shuffle produces the
   assignment). Show step-by-step results with green checks:
   「ハッシュ一致」「割り当て一致」. If any mismatch, show red with details.
4. Assignment table: slot → masked owner id.
5. Links: 「検証スクリプトをダウンロード」, 「アルゴリズム仕様」, 「開封映像を見る」.
6. Share button (copy URL) and OG image meta for social sharing.

Also build "/verify" (public verifier): a single input 「開封会IDを入力」 that routes to
/verify/[lotteryId]. No login, no navigation tab bar on public pages.
Use Web Crypto API for SHA-256.
Prototype algorithm (bx-shuffle-v1, an instance of §6.6.1): final = SHA-256(serverSeed|participantsHash|beacon);
Fisher–Yates from the last index, j = first 8 hex of SHA-256(final:i) mod (i+1); participants are one line
per purchased slot in purchase order. For PICK lotteries there is no draw: verify the seed commitment and the
participants-list hash only, and say so on the page. Downloads are blocked in some previews, so show the
verification script inline with a copy button. Provide a 「改ざんされた値で試す」 toggle in prototypes.

§9.2 全局设计系统与硬规则
You are building the web front-end for "Box Rush" (Japanese brand name: BOXラッシュ),
a Japanese trading-card "Breaking" platform
(group box-opening: users buy slots in a sealed booster box; the platform opens it on
camera at a promised time; each card goes to the slot that owns it).
All UI copy is Japanese. Instructions below are in English.

## Brand
- Product name: BOXラッシュ (primary, Japanese UI) / Box Rush (Latin, secondary).
- Use 「BOXラッシュ」 in page titles, header wordmark, emails and OG images.
- The name must not be used to create urgency: never pair it with countdowns,
  "急げ" / "今すぐ" style copy, or flashing effects (see UR7).

## Product principles (in priority order)
1. Evidence before action. Proof (seal photos, guarantee, fill progress, refund promise,
   seed hash) always appears ABOVE any purchase button.
2. Calm, trustworthy, collector-oriented. Not a casino, not a gacha.
3. Mobile-first. Most users are on phones.

## Layout
- User-facing pages: mobile-first, design at 390px wide, then adapt at two breakpoints:
  - >= 768px (tablet): full-width layout, 24px side gutter, 3-column card grid,
    chip rows wrap instead of scrolling.
  - >= 1024px (desktop): content max-width 1200px centered, 4-column card grid; the bottom
    tab bar is replaced by text links in the header (ホーム / LIVE / マイ枠 / コレクション,
    マイページ via the avatar); hover states on cards.
  Sticky bottom action bar for primary CTA on mobile. Bottom tab bar (mobile / tablet) with 5 tabs:
  ホーム / LIVE / マイ枠 / コレクション / マイページ (lucide icons: Home, Radio, Ticket,
  Package, User).
- Merchant and operations pages: desktop-first, 1280px, left sidebar navigation, dense tables.
- Spacing scale 4/8/12/16/24/32. Card radius 12px. Tap targets >= 44px.

## Visual language (browse patterns borrowed from Japanese online card shops)
- Horizontal scrollable category tabs at the top of browse pages.
- Rotating banner carousel under the tabs.
- Dense 2-column card grid of lotteries on mobile.
- Each lottery card: product photo, title, price per slot, guarantee line,
  a thick fill-progress bar with 「残り 2/12 枠」, opening time, and small tag chips.
- Full-screen overlay ONLY for reveal moments (see rule UR3).

## Design tokens (define as CSS variables; support light and dark)
- Background: near-white #FAFAF7 (dark: #111214). Surface: #FFFFFF (dark: #1A1B1E).
- Text primary #1A1A1A (dark: #F2F2F2); secondary #6B6B6B (dark: #A0A0A0).
- Primary accent (CTA, progress fill): deep indigo #3B3FD8.
- Trust / verified: teal #0F9D8A. Warning: amber #D98A00. Error: #D14343.
- Rarity highlight (only for revealed cards, never for unrevealed ones): gold #C9A227.
- Font: "Noto Sans JP" for UI; "JetBrains Mono" for hashes, IDs, timestamps.
- Numbers use tabular figures.

## Formatting
- Currency: ¥12,800 (yen sign, thousands separator, no decimals).
- Date/time in JST: 9/28(月) 20:00. Countdowns: 2日 03:14:05.
- Hashes: monospace, truncated middle (e.g. 3f9a…c21e) with a copy button; full value on tap.

## HARD RULES (violating any of these is a bug)
UR1. There are NO points, coins, credits, wallet balance, top-up, cash-out, or
    "sell back to platform" features anywhere. Never render a balance. Payment is always
    a direct payment per order. Refunds always return to the original payment method.
UR2. Never show profit/loss, expected value, "you won ¥X", ROI, or totals of card values
    for a lottery. Individual card reference prices may appear only on a single card's
    detail view, labeled 「参考価格」.
UR3. Animations may only REPLAY a result that is already determined and recorded.
    No slot-machine spinning, no roulette, no near-miss effects, no "almost got it".
    Every reveal must end with a visible link to verification (「検証する」).
    Every reveal is skippable (「スキップ」).
UR4. Whenever a user can buy, show: 「満員にならなければ全額返金」 and the sale deadline.
UR5. The seed commitment hash (「抽選シード（コミット）」) and its commit time are shown on
    the lottery detail page above the fold.
UR6. Recording is the source of truth. Any video player must allow turning OFF overlays
    to show the raw footage (「元映像のみ表示」).
UR7. Users have spending limits. Never add urgency dark patterns:
    no fake scarcity, no countdown pressure on purchase modals, no "only you" messaging.
    A factual 「残りわずか」 tag is allowed only when remaining slots <= 10%.
UR8. Self-operated lotteries always show a 「自営」 badge.
UR9. No live tipping / gifting UI.

## Accessibility
- WCAG AA contrast. Progress bars also show numeric text. Do not rely on color alone
  for states; pair color with icon + label.
